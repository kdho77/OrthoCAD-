## Gates

1. **stl_identity.** For every case, SHA-256 of the candidate STL equals SHA-256 of the baseline STL of the same fixture. The comparison is the full digest. Matching byte length or triangle count does not pass.
2. **cases_distinct.** On the tree under test, `stock_left`, `stock_right`, `narrow_heelcup_left`, `mortons_extension_left`, and `bottom_name_left` hashes are five different digests. This keeps a shared fixture from making identity pass vacuously.
3. **speed.** For every case, candidate loft seconds `<=` baseline loft seconds `* 0.90`. The runner reports both second values. A miss of the 10–15 s absolute aim is a residual in `RESULTS.md` and does not change this ratio.
4. **logs.** `executeCadOperatorProduction` on a synthetic left-foot row, with materialize and slice each waiting 30 ms and no network call, emits a JSON object with finite `loft_s > 0`, finite `slice_s > 0`, and `side: "left"`.
5. **geometry behavior.** Gate 1 is the behavior proof for geometry files. A helper edit that keeps these STL bytes identical passes gate 1. Any byte change fails gate 1.

## No-op

Running the gates with the candidate SHA equal to the baseline SHA must pass `stl_identity` and `cases_distinct`, and must fail `speed` and `logs`. The log failure counts when `executeCadOperatorProduction` finishes the foot (`status` succeeded, one materialize, one slice) and the captured output has no accepted `loft_s` / `slice_s` line. Main does not emit those fields. A second loft of main is not 10% faster than the first.

## Bad change

`prove_bad_change.py` must reject a one-byte STL edit, a same-length edit that keeps the triangle-count header, a transcript missing `loft_s` or `slice_s`, a non-numeric timing value, and a zero timing value. It must accept identical STL bytes and one valid timing line.
